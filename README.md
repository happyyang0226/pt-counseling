# 물리치료학과 지도교수 상담 웹앱

학생이 상담을 신청하고 사전 질문지를 작성하면, 지도교수가 일정 확정, 상담 일지, 후속 조치를 관리하는 웹앱입니다.

- 구성: HTML + JavaScript (빌드 없음) · GitHub · Vercel · Supabase
- 파일
  - `index.html` 화면 구성
  - `app.js` 동작 (로그인, 신청, 일지 등)
  - `style.css` 디자인 (모바일 대응)
  - `config.js` Supabase 연결 정보
  - `supabase/schema.sql` 데이터베이스 표와 보안 설정

## 1. Supabase 설정

AIDX 피드백 웹앱과 같은 Supabase 프로젝트(egwwmhmftixjmvrtivfm)를 함께 쓴다. 상담 웹앱의 표와 함수는 모두 `cs_` 로 시작하므로 다른 웹앱과 섞이지 않는다.

1. `supabase/schema.sql` 은 이미 적용되어 있다. (새 프로젝트에 다시 만들 때만 SQL Editor 에서 실행)
2. 교수 계정(ptyang@scjc.ac.kr)은 이미 관리자로 등록되어 있다.
3. **Authentication > Sign In / Providers > Email 에서 Confirm email 을 꺼야 한다.**
   (학생은 학번으로 가입하므로 확인 메일을 받을 수 없음)
4. `config.js` 에는 Project URL 과 publishable 키가 들어 있다.

## 2. Vercel 배포

1. vercel.com 에 GitHub 계정으로 로그인한다.
2. Add New > Project > `pt-counseling-app` 저장소 Import
3. Framework Preset: Other, 그대로 Deploy
4. 이후 GitHub 에 커밋하면 자동으로 다시 배포된다.

## 3. 사용 방법

- 학생은 한 학기에 3번 의무 상담을 받는다. 학생 화면 맨 위에 "이번 학기 상담 n / 3회"가 보이고, 교수 대시보드에는 3회 미달 학생이 횟수와 함께 나온다. 횟수는 교수가 쓴 상담 일지 수로 센다.
- 상담 분야: 취업, 학업, 진로, 학교생활, 교우관계, 기타
- 교수가 상담 일지를 쓸 때 분야별 피드백을 적으면(cs_feedback) 학생 화면 "교수님 피드백"에 바로 나타난다(Supabase Realtime). 학생 이력에서 보낸 피드백과 학생 확인 여부를 볼 수 있고, 신청 없이 진행한 상담도 "상담 기록·피드백 추가"로 기록할 수 있다.
- 학생: 학번·접속 코드(6자 이상)로 가입 → 개인정보 수집·이용 동의 → 상담 신청(사전 질문지, 고민 크기 1~5) → 내 상담 내역 확인, 익명 질문
- 교수: 교수 탭에서 로그인 → 대시보드(주의 학생, 7일 일정, 미상담 학생) → 상담 시간 열기 → 신청 확정 → 일지 작성·완료 → 학생별 이력, 후속 조치, 익명 질문 답변
- 학기말 보고: 학생별 이력 탭에서 CSV(엑셀) 내보내기 — 학생별·분야별 횟수, 상담 기록 전체(교수 메모 포함 여부 선택)
- 교수 화면 위쪽 "반 보기"에서 전체 / A반(1반) / B반(2반)을 고르면 대시보드, 신청 목록, 학생별 이력, 후속 조치, 명단, CSV 내보내기가 모두 그 반만 보여 준다. 반은 명단(cs_roster.class)에 저장되고, 명단 표에서 학생별로 바꿀 수 있다.
- 명단·설정 탭에서 학생상담센터 전화번호를 넣으면 학생 화면 하단과 위기 안내에 표시된다.

## 보안

- 학생은 자기 신청만 보고, 대기 중인 신청을 취소하는 것만 할 수 있다.
- 상담 일지(교수 메모 포함)는 교수만 볼 수 있다. 학생에게는 "공개 요약"만 보인다.
- 고민 내용에 위기 표현이 있거나 고민 크기가 5점이면 학생 화면에 도움 연락처(109, 1577-0199, 학생상담센터)가 뜨고, 교수 대시보드에 빨간 경고가 붙는다. 4점은 노란색 주의 표시.
- 익명 질문은 작성자 정보를 저장하지 않는다. 답변하고 공개로 둔 질문만 학생들에게 보인다.
- 로그인 정보는 탭을 닫으면 지워지고(sessionStorage), 20분 동안 사용하지 않으면 자동 로그아웃된다.
- service_role 키는 절대 코드에 넣지 않는다.

## 단계별 상담 신청 (2026-11-03 개편)

- 학생 신청 흐름: 상담분야 → 고민 고르기 → 상담 준비하기 → 방식·시간 → 신청 내용 확인 → 완료. 한 번에 한 단계, 진행 표시, 이전/다음, 모든 답은 버튼(글쓰기는 선택).
- 분야·고민·질문 보기는 `cs_items` 표에 고유 ID로 들어 있다(예: `study.exam`, `since.1m`, `mode.online`). 문구를 바꾸려면 이 표의 label만 고치면 된다.
- 신청(`cs_requests`)에는 ID로 저장한다: area_id, concern_ids, first_concern_id, other_concern, since_id, impact_id, help_ids, mode_id, slot_id, concern(추가 이야기). 서버 트리거가 ID를 검증한다.
- 같은 신청이 두 번 저장되지 않도록 client_token(고유값)을 쓴다. 같은 시간 중복 신청은 서버에서 막는다.
- 선택 응답으로 위험도를 자동 판정하지 않는다. 학생이 직접 쓴 글에 위기 표현이 있을 때만 담당자 화면에 "글을 먼저 확인"으로 표시한다.
- 응답은 화면 메모리에만 두고 주소(URL)나 브라우저 저장소에 남기지 않는다.
- 개인정보 안내의 보관 기간은 "학교 개인정보 처리방침에 따릅니다"로 두었다. 학교 양식이 확정되면 index.html의 동의 화면 문구를 바꾼다.
